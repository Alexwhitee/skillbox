# Chen 用量报表

复用 Fastify + MySQL 报表服务和已有脚本。本 skill 依赖现有服务或本机源码，不包含数据库和部署凭据。

## 入口

- 项目通常位于工作区的 `jiaoben/zong/chen-wufuqi`。优先用户指定目录；路径不匹配时，在当前工作区定位 `package.json` 名称为 `usage-report` 的项目；找不到时再请用户提供项目位置。
- 先读 [references/operations.md](references/operations.md)，按需要选 API、异步导出或现有脚本。
- `REPORT_BASE_URL` 是报表服务，不是 NewAPI 源站。不得沿用脚本内置的历史公网地址、项目、用户名和日期；从当前请求或配置确定。
- 普通查询/导出不需要源库密码，不自动触发源数据库同步、回填、迁移或部署。

## 流程

1. 确定服务地址、项目、用户/筛选、时间和格式。登录后通过 `/api/sources` 发现项目，不猜 key；凭据从环境读取，不回显。
2. 无时区时间默认北京时间并说明。API 使用 Unix 秒；脚本接受无时区 `YYYY-MM-DD HH:mm[:ss]` 并自行追加 `+08:00`，不能传带 Z/偏移的字符串。验证有效且结束不早于开始；不默认全部历史。
3. 先查同步状态，再查用量。查询反映已同步数据；零条不能证明源站没有用量。同步落后、失败或覆盖范围不明时说明新鲜度限制。
4. 小范围查询用 API；按用户名导出 XLSX 可复用脚本。一般异步导出用服务端任务；Worker 不运行而明细 API 可用时，可用 `export-usage-direct.mjs` 分页导出。“direct” 仍调用报表 API，不是直连 MySQL。
5. 核实唯一用户 ID。用户接口最多 1000 条，脚本找不到不能断言用户不存在，不能去掉筛选导出全项目。重名/显示名歧义时用明确 ID 或补充信息。
6. 保存异步任务 ID，轮询到 `completed/failed/expired`；超时先查原任务和 Worker，不重复建单。分页以 `meta.hasNextPage/nextCursor` 为准，不把第一批当全部数据。
7. 检查文件存在、非空和数据行数。交付绝对路径、项目、筛选、北京时间范围、记录数和同步限制；中途失败文件标为不完整。

## 边界

- Cookie 只保留在内存或受限临时文件，不输出环境、密码、源库连接或完整会话。
- 脚本同项目/用户/日期可能同名，每次使用独立输出子目录避免覆盖。
- 汇总按 `hour/day/user/model`；`quota` 保持原始额度含义，未验证计费规则不能说是人民币或美元。
- 只有用户要求立即同步才调用对应项目同步接口；查询授权不等于部署或改生产库授权。
