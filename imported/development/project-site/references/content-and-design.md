# 内容与设计

## 先组织信息

| 访客要做什么 | 页面给他什么 |
| --- | --- |
| 判断是否值得继续看 | 项目对象、解决的问题、可观察的结果、主要行动入口 |
| 理解真实用法 | 一个具体案例，依次展示输入、操作与产物，说明必要条件 |
| 跑通第一步 | 真实前置依赖、可复制命令、最小成功示例和预期结果 |
| 查清细节 | 手册、配置和行为说明、适用边界、排障和 FAQ |
| 找到源头 | 已核对的仓库、文档、项目许可与仓库权限提示 |

首页提炼事实并展示项目。长说明由现有 README 或 docs 生成，构建处理相对链接、表格和锚点。区分终端命令、AI 会话指令与配置片段。示例参数的替换方式、示意演示和计划功能在靠近内容的位置标明。

## 设计成这个项目的站

构建前选定一个视觉重心、一组颜色及一种页面节奏，判断它们是否能帮助访客理解当前项目。设计从真实首页内容起步，再用同一套排版、颜色、间距和组件走到手册。已有站有品牌时沿用其标识和视觉语言，优先处理首屏层级、阅读密度和主操作入口。

| 项目类型 | 可从哪些材料起步 |
| --- | --- |
| CLI、SDK 或自动化工具 | 一条真实命令与可核实的结果、前后对照，或包含关键产物的流程 |
| 桌面或 Web 应用 | 去除隐私信息的实机截图，用局部放大解释主要操作 |
| 工作流或知识项目 | 一张带可读说明的流程图、真实产物样例或章节路径 |

- 主视觉承载真实信息。次要内容按用途使用列表、流程、对照或正文。克制使用重复卡片、编号、徽标、渐变和装饰文案。主操作用动词清楚写出目的，其余入口保持较弱的视觉权重。
- 正文默认从 16px 设计，手册中文行宽可从约 32–40 字起调，英文可从约 60–75 字符起调。中文标题保留正常字距和自然断行，长英文标题随容器收缩。用真实双语文案定布局。
- 一套可复用的颜色、边框、间距和字号变量覆盖首页与手册。保持正文对比、可见焦点和清晰的链接状态。代码与数据表只在各自容器滚动。
- 顶部及手机视图保留直接可见的语言链接。仓库入口桌面明显可达，移动端可在菜单中。菜单按钮维护 `aria-expanded`。主要功能支持键盘，动画响应 `prefers-reduced-motion`。
- 按实际内容决定是否加筛选、搜索、复制或流程切换。复制成功后再确认，失败提示手动复制。搜索文本按数据处理，长手册按语种返回结果。
- 使用项目真实素材。截图检查隐私、裁剪和清晰度，给出有意义的替代文本。可生成示意插图解释概念，明确标注用途。字体优先沿用项目资产或系统字体。

[用户的 G Skills 站](https://g-skills.pages.dev/)可作为内容深度和流程说明的参考。站点源目录、样例和配色都按当前项目确定。

## 浏览器验收

对照 1440px、768px、390px，并抽查 320px。检视中英文真实内容的首屏层级、正文行长、菜单触达、可点区域、局部滚动与整页溢出。实际点击主要行动、手册、语言开关及已有交互，测试键盘焦点和控制台。修完后按相同路径再走一遍。
