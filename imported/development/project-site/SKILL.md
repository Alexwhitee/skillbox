# 项目介绍网站

交付可浏览的项目介绍站，让第一次访问的人知道项目解决什么、怎么工作、如何上手、去哪里查细节。默认简体中文首页，可切换到英文的对应页面。沿用项目已约定的语言、路由和品牌要求，发布以用户请求为准。

## 核对项目与选型

读项目指令、README、公开文档、关键入口和部署配置。核实目标用户、典型任务、输入输出、安装与最小成功示例、仓库、许可和已知限制。以可追溯的代码、文档和运行结果支撑页面文案。标注计划功能、示意演示和站点链接的权限要求。

优先在现有站点上改，保留有效内容、已有链接、文档源和部署方式。新建时按 [选型与样站](references/site-options.md) 选方案。几页展示与手册可从随附的无依赖静态样站起步。文档量大且需要成体系的侧栏、搜索或版本化时，再考虑文档框架。

## 内容、视觉与中英文

读 [内容与设计](references/content-and-design.md) 和 [中英文站点](references/bilingual.md)。先定访客的首要行动、项目特有的主视觉、首页叙事与手册边界，再把同一设计系统用到两种语言。视觉参考可借鉴结构和节奏，配色、版式、图形来自当前项目。

- 首页先讲定位和具体用例，给出快速开始、手册与真实仓库入口。复杂项目设独立手册。已维护的 README 和文档继续作为事实源。
- 切换入口在桌面与手机上都可见，首页和手册均可双向进入对应译页。正文、导航、操作反馈和页面元数据一起本地化。保留原有深链接，使用稳定的章节标识。
- 采用真实截图、可核实的输入输出、交互流程或用项目数据绘制的图。与技术栈现有交互相容，默认使用同源资源，无分析统计或第三方运行时调用。

## 构建与验收

本地运行实际构建与预览，检查输出目录、页面、资源、站内链接和锚点。使用已有检查或补一个可重复的路由与链接自检。长文继续用已有 Markdown 渲染器，构建输出定向到专用发布目录，生成产物纳入项目忽略规则。

在浏览器打开实站，至少看中英文桌面与窄屏截图，实际操作首页和手册双向切换、直达与刷新、键盘导航、主要交互。核对长英文标题、代码和表格、控制台与整页溢出。解决看到的问题后重验。依据实测结果报告覆盖范围。

## 发布与交付

用户要求 Cloudflare 发布时，执行 [Cloudflare Pages 发布](references/cloudflare-pages.md)，沿用已有 Git 集成或使用 Pages Direct Upload。核对账号、项目归属和生产分支，上传前确认发布目录仅包含可公开资产。线上核验两种语言的首页与手册、切换、静态资源以及本次产物。

将已核验的生产 URL 挂到项目 README。若 README 是构建源，更新后重建并发布最终产物。记录源码、构建、预览、检查、语言内容入口，以及实际采用的发布命令。交付时给出已核验的预览或生产地址和实际部署状态。Git 提交、推送与合并按用户授权处理。
