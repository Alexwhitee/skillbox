# 模板：详细改动说明

给开发者看，目的是**读完能接手、能改、能回滚**。可以写路径、函数名、配置键、命令。尖括号换成内容。「测试改动」「验证」「回滚」三节保留。没有的小节整节删掉，不要写「无」。图的规则见 [charts.md](charts.md)：数量对比用 `█` 表，行为变化用顶格 `graph`，不要 `xychart-beta` 和 `flowchart`。成稿参照本项目 `docs/changes/2026-11-23-2/2026-11-23-无导向句式抽样-detailed.md`。

节的顺序：元信息 → 问题 → 整体流程 → 每个改动一节 → 一个真实的例子 → 没改什么，怎么保证没有副作用 → 使用与调整 → 测试改动 → 验证 → 已知局限 → 常见疑问 → 未完成 → 回滚。

## <每个改动一节，小标题写它是什么>

`path/to/file`：`<函数或接口签名>`，<这个文件现在做什么，一句。>

**逐步讲解**，把「怎么做、为什么这样做」讲到读者不看代码也能复述：

- 规则、取值和约束用表：规则、理由、影响的数量、例子。
- 有计算的写出算式和结果，例如「64 − 1 − 10 − 2 = 51」，数字用代码实际算一遍再写，不凭印象。
- 随机或抽样逻辑：种子是什么、结果是否可复现、有没有重试和兜底分支。
- 默认值、报错条件、边界情况各一条。

**关键代码或提示词原文**，用代码块贴真正起作用的那一小段，不贴整个文件，原文一字不改。代码块后用表逐行讲作用：

| 这一行 | 作用 |
|---|---|
| <代码或提示词里的一句> | <它让什么发生> |

- <有意留着的兼容行为，写明原因>
- <为什么默认行为不变；传错参数会怎样>

下一个改动另起同级标题。改动很小就并进上一节。

行为链路变了才加 `graph`，图内每行顶格，节点不超过 20 字，放不下的写在图下。同参数重跑时哪个字段变、哪个不变，写在一处。

## 验证

```powershell
<可复制的命令>
```

原始摘要，原样抄：`<例如 14 failed, 953 passed, 207 errors>`，并写基线的原始摘要。

失败集与基线：<一致 / 多了哪些、少了哪些>。

离线或对照实验：一张改前 / 改后的条形表或数字表，加一句方法。没跑的写「未执行：<项>」。样本少于 10 不用条形。

**用模型评审时**，在这一节写全：

- 评委设置：几个评委、分几轮、每个评多少条、两组顺序怎么随机、格式和证据怎么核验。
- 评分标准的修订：修订了什么、为什么、是不是在看到结果之后改的；修订前后的数分开写。
- 结果表：每项的改前、改后、差、95% 区间；区间跨 0 的项明确写「区间跨 0」。每一轮单独的差值也给出，不只给合并值。
- 评委一致性：逐项一致率，两轮判断不同的情境数，一致率低的项单独标出。
- 有变差的指标时，**拆开看原因**：按类别或句型拆，区分「同一类里变差了」和「类别构成变了」，给出支持的数；再说明评分标准有没有明显偏向、还有哪些会放大差距的地方。
- 与旧标准或旧版本的对照，只评了一轮时写明，并说明区间是否跨 0。
