# 日报格式和声音

撰写前通读。格式沿用团队现有实习日报，不另起一套标题。

## 格式

```
# 实习日报-姓名

# 2025年05月20日

### 1 数据标注-QQ炫舞

1.1 群内答疑与标注任务分配

1.2 每人埋点2条

● 565-李焯华，有一个人名有错字

● 456-赖浩然，后面少内容了

### 2 CommunityNPC

2.1 ……
```

- 模块：`### N 名称`。序号后不加点。已有文件如果写成 `### 1. 名称`，跟文件走。
- 子条目：`N.M` 加空格，是普通段落，不是 Markdown 列表。模块 2 下面是 `2.1`、`2.2`。
- 明细：`●` 加空格。
- 只有一条工作线，或都是零散事务时，不写模块标题：

```
# 2025年07月22日

1. 根据需求实现了一下意图分类的逻辑，……

2. 用相似度最高的 query 的一级、二级意图作为分类结果。……
```

- 新建内容：段落之间空一行。不要每句之间都插空行。
- 追加到已有文件：空行、标题层级跟那个文件，不改旧日期。
- 请假：`休假一天` 或 `请假`。

## 一条里写什么

不设「今日工作 / 完成情况 / 问题 / 计划」小标题。

| 内容 | 写在哪 |
|---|---|
| 做了什么 | 子条目开头 |
| 结果 | 同一条里的结果句，或一张表 |
| 问题 | 同一条里的「跑的时候报了……，是因为……」；同类问题多就用 `●` |
| 下一步 | 仅当材料里有，收在句尾。不单独开清单 |

句序：背景，动作，结果。没有的环节不补。说完就停，不要另起一段总结。

声音样本（一条说完一件事，逗号可以这样接，不要改成一串短句）：

> 2.1 计算了一下稀疏检索的时间开销，bm25_retrieval初始化的时间在0.27s，检索时间在0.003s，由于之前的代码逻辑在每一次检索的时候都会重新初始化一次稀疏检索器，占据了大量时间开销。将稀疏检索器的初始化放在了npc的init，并且设置了环境变量EFFECTIVE_TIME，根据这个环境变量来过滤稀疏检索器初始化时使用的文档。同时如果未传入有效日期，那么则会默认使用环境变量中的时间戳。

这是样本，不是填空模板。信息没这么多就写短。不要按「第一个原因、第二个原因」去凑。

## 详略

| 事项 | 篇幅 |
|---|---|
| 答疑、派活、开会、验收 | 1 行 |
| 质检、埋点 | 1 行概述 + `●` 列出「编号-人名，问题」 |
| 开发、修 bug | 一段：原因，改法，提交了没有 |
| 实验 | 设置用一句话，数字用表，表后一行解释缩写或异常 |
| 调研、读源码、读论文 | 写结论。没有结论就写看了什么，或 `【待补充：要点】` |
| 没做完 | 写到哪一步、卡在哪 |

一天 1–3 个模块，每个模块 1–4 条。不要拆开凑条数，也不要把实验压成「做了测试」。

## 声音

- 省略主语「我」。团队共同决定可以用「我们」。
- 动词用完成体：改了、修了、加了、测了一下、提交了 mr。进行中就写「正在查」「还没跑完」。
- 中文标点。英文名直接嵌进句子，不加反引号，中英文之间一般也不加空格：修改了base_npc代码中的初始化和检索部分。
- 括号用来补充，不用来拔高：（得分小于 2）、（已改）。
- 百分比保留材料里的小数位，不自行四舍五入到「好看」的数。

Humanizer-zh 在这里的用法：删掉没有信息的句子，保留上面这种口吻。一句如果只是在夸效果，删掉，留下事实。不要为了「像人」另加语气词，也不要把样本里的长句改成短句排比。

材料没写的论文观点、耗时、召回率，不能在润色时补上。

## 数字

对比用表。第一列是对象，表头是设置。表后一行说明缩写。正文不把格子再读一遍，只写表里看不出的判断。

```
|benchmark|top3|top5|top8|top8 w/o date_filter|
|---|---|---|---|---|
|qa1(全文本提问)|89.3%|94.2%|95.9%|88.8%|
|qa2(分段提问)|88.0%|94.8%|97.3%|92.0%|

w/o date_filter：不加时间过滤
```

上面是版式。数字必须来自用户材料。

用户给了截图就放 `![](链接)`，没给不补。样例原文（bad case、过滤规则）直接贴，前面一句「例如」。链接写成 `[文档名](链接)`。

日报默认用表，不用 mermaid，也不用字符画的条。团队文档经常不渲染图。

## 调研

读论文：链接一行，标题一行，然后写材料里已经有的要点（旧方法的问题、本文做法、关键设计）。用户没给要点就不要自己概括论文，只写「看了 <标题>」或占位。

读源码：先写「结论：」，再用 `●` 列用法。

竞品：写清测的是谁、什么场景，再写观察到的差别。

## 团队简版

团队文档日期倒序，每人一块：

```
## 2026年10月27日

@yanxuxi(郗延旭)

1. 熟悉灵感词和对话数据的项目文档。

2. 数据管线：修了空日期传入时的报错；初始化挪到 npc 的 init。
```

- 日期用 `##`。姓名写 `@英文ID(中文名)`。
- 一条一句，最多两句。留对象和结果，省过程。
- 不用 `###`，不用 `●`。

## 不要这样写

| 空 | 具体 |
|---|---|
| 今天完成了数据处理工作，取得了良好效果。 | 2.1 修改了excel转json的代码，可根据「是否入库」字段跳过不需要入库的数据，总计筛掉了497条，剩余920条。 |
| 学习了相关技术，提升了自身能力。 | 2.3 看了一些稀疏检索相关的内容，以及langchain BM25Retriever的源码。 |
| 修复了一些bug。 | 2.1 修复了代码中传入知识板块或有效日期为空列表或者空字符串时存在的bug。 |
| **今日工作：** … **问题：** … | 用 `### N` 和 `N.M`，问题写在同一条里 |
| 使用 `base_npc` 的 `retrieve()` | 用 base_npc 的 retrieve |
| （材料没给数）召回率到了 98% | 【待补充：召回率】 |
