# 实习日报

把一天的笔记、口述、git log、聊天记录或实验数据整理成日报。格式见 [references/style_guide.md](references/style_guide.md)。空白骨架见 [assets/daily_template.md](assets/daily_template.md)。

只写日报。用户要周报，或要单独的「明日 TODO」清单时，说明本 skill 不写这两样，然后只交日报。笔记里已经写到的下一步，可以在对应条目末尾收半句；没有就不加。

## 写之前读

1. 读 [references/style_guide.md](references/style_guide.md)。
2. 读 `C:/Users/yanxuxi/.agents/skills/Humanizer-zh-main/SKILL.md` 的「编辑约束与优先级」「文体与作者声音」「模式的使用方式」和「交付前核对」。

日报的声音以 style_guide 里的范例为准：省略主语，一句里把事说完，「测了一下」「改了」可以留。Humanizer 用来去掉空话、假拔高和重复，不要把日报改成公文，也不要把范例里的长句拆成短句排比。不要在日报里提到 Humanizer。

## 流程

### 1. 收集

- **日期**：用户没说就用当天。「昨天」「上周五」按当天推算，跳过周末。标题写成 `# YYYY年MM月DD日`，月日补零。
- **姓名**：只有文档总标题或团队简版的 `@英文ID(中文名)` 才需要。材料里没有就问。
- 用户给了已有日报文件时，读最近 3–5 天：沿用已有工作线名称，衔接前一天提到的问题，空行习惯跟该文件走。
- 先读完原始材料再写。材料里没有的数字、人名、结论、论文内容，不补。缺了就写 `【待补充：xxx】`，并在回复里提醒。

### 2. 归类

- 收成 1–4 条工作线。名字用项目或模块的现成叫法。
- 例行事务放前面，写一行。开发、实验放后面。
- 当天只有一两件零散的事：不加模块标题，直接 `1.` `2.`。

### 3. 写

默认**个人日报**。用户要贴进团队文档时，再给一份**团队简版**（由个人日报压成每条一句）。两版都要时，先个人，后团队。

一条核心事项写成一段：为什么做，做了什么，结果。说完就停，不要再补一段总结，也不要拆成提纲。范例里用逗号接起来的长句可以留。结果是一组对比数字时用表，这段里不要把表再念一遍。

例行事项一行。质检问题用 `●` 逐条列「编号-人名，问题」。

请假只写一行：`请假` 或 `休假一天`。

### 4. 核对后再给

- 编号是 `### N 名称`、`N.M`、`●`，和 style_guide 一致。
- 数字、人名、版本号、路径与材料一致。
- 没有「圆满完成」「显著成效」「进一步提升了能力」「综上所述」。
- 表或条目里已经写过的，不在下一句复述。
- 「可能」「正在查」「还没跑」保持原样，不写成已经完成。

### 5. 放哪里

- 只要文本：写在回复里。
- 指定了个人日报文件：按时间正序，追加到末尾。
- 指定了团队文档：按时间倒序，最新日期在最前。当天标题已在，就把 `@ID(姓名)` 插到该日期下。
